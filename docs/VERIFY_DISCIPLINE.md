# 验证纪律：任何验证都不许改用户状态

> 一句话：**验证是只读的。**测完磁盘上的东西必须和跑之前一模一样 ——
> 要还原就还原成"跑之前的值"，绝不许还原成"默认值"。

这条纪律的代价是真实付过的：底部面板的"展开 / 页签 / 高度"是用户的持久偏好
（存在 `<数据目录>\config.json` 里），而验证脚手架接过二连三地把它写掉，
用户看到的现象是**"我明明展开着关的程序，下次进来是收起的，也不在我看的那个页签"**
—— 也就是"这个偏好根本没落盘"。查了半天代码，其实是被自己人擦掉的。

## 已经发生过的事故（都是同一类）

| 入口 | 干了什么 | 用户看到什么 |
|---|---|---|
| `-open globaltag` | 自测为了截图把底部栏切到日志视图；面板本来就停在日志时，这次"切换"被当成"点当前页签" → 收起 → 把 `bottomPanelOpen=false` 写进**真实** `data\config.json` | 下次启动面板是收起的 |
| `-open bottompanel` / `sitespanel` / `connpanel` / `netpanel` … | 同类入口都会切视图 → 把 `bottomPanelView` 改成自测需要的那一页 | 下次启动停在"流量统计/日志"，不是自己上次看的页签 |
| `-open netpanel` | 自测真的点了「保存」 → 把空闲断开从 300 写成 240 | 一个自己没改过的设置变了 |
| （人工"恢复现场"） | 把 `bottomPanel*` 直接改回 `false / logs / 260` | 偏好被"恢复"成了出厂值 |

事故的共同点：**"验证"动的是别人的状态，而不是验证自己的临时状态。**

## 三条要求

1. **默认隔离**：所有会启动程序的自测脚本，都要把数据目录指到临时目录
   （`CHAINPROXY_DATA_DIR` → `.cache\...` 下），需要真实节点就**复制**一份配置过去。
   真实 `data\` 只读。
   - `scripts\ui_shot.ps1`：已经把数据目录隔离到 `.cache\uishot-data`，
     跑完还会核对真实 `config.json` 的 sha256 —— 变了就**报错**（不是默默放过）。
   - `scripts\test_panel_prefs.ps1`：端到端验证底部栏偏好，全程在临时副本上跑，
     同样核对真实配置的哈希。
   - `scripts\test-sysproxy.ps1`：测的是系统代理注册表，改动由 finally 还原成**原值**
     （这是"先备份再还原"那条路的正确写法，可以照抄）。
2. **测完还原成原值**：任何不得已写到共享位置（注册表、系统代理、剪贴板）的验证，
   必须在 `finally` 里还原成**跑之前记下来的原值**；不许用"默认值"顶替原值。
3. **产品自己也要守住**：验证脚手架不该是唯一的防线。
   - `-open <面板名>` 驱动的界面只改显示、不落盘（`ui.devDriven`，
     见 `desktop/frontend/src/App.vue` 与 `components/BottomPanel.vue` 的 `persist()`）；
   - 设置没加载完之前不许写回设置（`store.settingsLoaded` 门闩）；
   - "恢复默认设置"不动界面布局偏好（`desktop/api.go` 的 `ResetSettings`）。

## 怎么验证"底部栏偏好真的记住了"

用户口径（也是唯一算数的口径）：

1. 打开程序 → 点底部栏的「展开」→ 切到某个页签（例如「网站测试」）→ 拖一下高度；
2. 退出程序（托盘 → 退出 ChainProxy，或右上角 × 收进托盘后从托盘退出）；
3. 重新打开 → 底部栏应当**仍然是展开的**、**仍然停在那一个页签**上、高度也还是刚才拖的。

机器口径（一条命令，跑完只看最后一行）：

    .\scripts\test_panel_prefs.ps1 -Shot

它会断言：启动后偏好没被默认值反写、强杀重开后仍记得、自测入口跑过之后也不被改写，
并且用户真实的 `data\config.json` 哈希前后一致。加 `-Shot` 会在
`.cache\shots\panel-prefs-after-restart.png` 留一张"重启后应该长这样"的图。

## 已知还没彻底做到的地方（写在明面上，别当成没事）

- `scripts\test-sysproxy.ps1` 仍然直接用仓库里的 `data\`。它为了断言必须拿到全局节点的
  真实端口，同时会把 `settings.systemProxy`、`data\chainproxy.log` 写到真实目录里
  （注册表那部分是"先备份、再还原成原值"，做法是对的）。它**不碰**底部栏偏好，
  所以这一轮没动它 —— 要彻底合规，得照 `ui_shot.ps1` 的做法把它也搬到临时数据目录上。
- `scripts\test_e2e.ps1` 读的就是真实 `data\config.json`（要测真实链路，这是故意的）。
  它只读不改：进程是被强杀的，不会走到"退出时落统计"那条写盘路径。

## 临时目录里的东西

隔离目录里的 `config.json` 是真实配置的**副本**（含节点凭据），所以它只能待在
被 gitignore 掉的 `.cache\` 里，永远不要提交、不要往外拷。程序启动时会顺手把
这份副本的目录权限也收紧（`config.EnsureDataDir`），不再需要它时直接删
`.cache\uishot-data`、`.cache\panel-prefs-e2e` 即可。
