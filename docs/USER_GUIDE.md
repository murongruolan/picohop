# ChainProxy 使用手册

> 一句话：把本地主流客户端当"前置"，把你的住宅 IP 服务商当"出口"，
> ChainProxy 把两者串成一条链，开一个本地端口给你用。

---

## 1. 三分钟上手

1. **启动主流客户端**，确认 `127.0.0.1:10808` 能用（mixed 协议，SOCKS5/HTTP 都行）。
2. **运行 `dist\chainproxy.exe`**（双击即可，不会有黑框）。
3. **检查前置代理设置**：默认已经是 `socks5` / `127.0.0.1` / `10808`，一般不用改。
4. **添加住宅代理**：点「+ 添加住宅代理」
   - 类型选 `socks5`（或 `http`）
   - 快速导入框里粘贴：`fuckoai_2026-zone-custom-region-US:HVu78BgQcny7@hk.rrp.bestgo.work:10000`
   - 点「解析并填入」，会自动拆成地址/端口/用户名/密码
   - 本地端口填 `10810`（默认就是这个）
   - 点「确定」
5. **点顶部「启动」**（如果启动时勾选了"启动即占用端口"，这一步可以跳过）。
6. **点「一键测试」**，日志里应该出现：
   ```
   ✅ 前置代理        出口 IP 103.115.108.31   延迟 1176 ms
   ✅ 住宅代理1       出口 IP 184.152.45.164   延迟 4275 ms
       ✅ 链式代理生效：前置 103.115.108.31 → 住宅 184.152.45.164
   ```
   **两个 IP 不同 = 成功。**
7. **在浏览器/软件里填代理 `127.0.0.1:10810`**，走的就是住宅 IP。

## 2. 界面说明

### 顶部状态栏

| 元素 | 含义 |
|---|---|
| ● / ○ | ● 绿 = 正在运行并占用端口；○ 灰 = 已停止，不占任何端口 |
| 文字 | `运行中 · 2/2 条链路已占用端口` |
| 「启动 / 停止并释放端口」 | 主开关。点"停止"会立刻释放全部本地端口并断开所有连接 |
| 「一键测试」 | 分层测试前置 + 每条链路，并对比两个出口 IP |

### ① 前置代理

| 字段 | 说明 |
|---|---|
| 类型 | `socks5`（推荐）/ `http` / `直连` |
| 地址 / 端口 |主流客户端的监听地址，默认 `127.0.0.1` / `10808` |
| 用户名 / 密码 |主流客户端没开鉴权就留空 |
| 超时 ms | 建立前置连接 + 前置握手 + 请求住宅服务器的总超时，默认 10000 |

「直连」= 不使用前置，直接连住宅代理。国内环境基本用不到，留作对照排障用。

### ② 住宅代理（出口）

表格列：`状态 | 名称 | 类型 | 本地端口 | 住宅服务器 | 流量↑/↓ | 状态说明`

| 符号 | 含义 |
|---|---|
| `●` | 运行中，端口已占用 |
| `○` | 已停止（主开关关闭，或链路启动失败） |
| `⚠` | 错误，具体原因在"状态说明"列 |
| `▶` | 当前选中的行（用 ↑/↓ 键移动） |

按钮：
- **启用/禁用**：单独开关某条链路（禁用后它的端口立即释放）
- **测试选中**：只测当前这一条
- **▲ ▼**：调整顺序
- **删除**：删掉配置并释放端口
- **编辑**：改配置（运行中改会自动重启这条链路）
- **+ 添加住宅代理**：新增

### ③ 运行状态与测试输出

所有启动、连接、失败、测试结果都在这里，带时间戳。
「清空」「复制全部」「打开配置目录」。

### 底部状态栏

显示前置代理的实际描述、配置文件路径，以及"本程序不注册任何开机自启动项"的声明。

## 3. 添加/编辑对话框

| 分组 | 内容 |
|---|---|
| 顶部 | 名称、类型（含「启用此代理」勾选） |
| 快速导入 | 粘贴 `user:pass@host:port` 或 `socks5://...` 后点「解析并填入」 |
| 本地端口 | 浏览器/软件里要填的地址和端口；端口账号密码默认留空 |
| 住宅代理服务器 | 只有 socks5/http 类型才显示 |
| WireGuard 隧道 | 只有 wireguard 类型才显示（**实验性**，见第 6 节） |

保存前会做四重校验，任何一项不过都会在对话框底部用一行红字说明原因：

1. 端口范围 1–65535
2. 不能与**前置代理端口**相同（否则自己连自己，死循环）
3. 不能与其它住宅代理的端口重复
4. 若主开关开着，端口必须真的能绑定（试绑定）

## 5. 常见问题

### Q：测试说"链路出口 IP 与前置出口 IP 相同"

说明流量没有真正走住宅代理。常见原因：
- 住宅代理不支持这种连接方式（部分厂商的 SOCKS5 只做 TCP 透传，嵌套后可能退化）
- 住宅代理账号密码错误
- 你在"前置代理"里选了「直连」，等于没有前置

### Q：状态列显示"端口被占用"

说明这个本地端口被别的程序（很可能是上一个没退干净的 ChainProxy 实例）占着。
换一个端口，或者先关掉占用它的程序。

### Q：界面偶尔卡住 / 点了没反应

本程序把耗时操作全放在后台线程，正常不会卡。
真遇到就关掉重开 —— 端口会由操作系统自动回收，不会有残留。

### Q：住宅 IP 是动态的，每次都不一样

正常。代理商的每次连接可能分配不同出口 IP。本程序**每条客户端连接都会新建一条完整链路**，
所以浏览器一次会话里不同网站可能看到不同 IP。这是特性不是 bug。

### Q：为什么不开"开机自启动"？

按需求明确不注册任何自启动项（不写注册表 Run 键、不建计划任务、不装服务）。
需要开机就用就手动启动一下，或者把 exe 拖到"启动"文件夹里自己放。

## 6. WireGuard（已实测可用）

ChainProxy 用**纯用户态**方式实现 WireGuard：不需要 wintun 驱动、不需要管理员权限、
不改动系统路由表，也不会影响机器上其它程序。

```
你的软件 → 127.0.0.1:10812 → gvisor 用户态网络栈 → wireguard-go
        → SOCKS5 UDP 封帧 → 前置代理(主流客户端10808) → WireGuard 服务端 → 目标
```

### 第一步：先在本机生成密钥（最重要的一步）

WireGuard 的安全模型是**私钥不出本机**：

```
① 本机生成一对密钥            →  ② 把【公钥】交给服务端登记为 peer
                                      ↓
④ 本机填：自己的私钥            ←  ③ 服务端回给你：它的公钥、Endpoint、
   + 服务端的公钥 + Endpoint         分配给你的隧道地址（如 10.8.0.2/32），
   + 隧道地址 + AllowedIPs            以及可能的 PresharedKey
```

**私钥任何时候都不要发给服务端。** 服务端只需要你的公钥。

两种生成方式（任选）：

**A. 图形界面**：添加住宅代理 → 类型选 `wireguard` → 点「生成密钥」。
它会自动填好私钥，并把「本端公钥」显示在下面一行 —— 直接点「复制公钥」交给服务端即可。
如果你已经有了私钥，粘进「私钥」框，下面那行会**立刻**算出对应的本端公钥。

**B. 命令行**：

```powershell
chainproxy.exe wgkey           # 生成一对新密钥
chainproxy.exe wgkey -psk      # 顺带生成预共享密钥
chainproxy.exe wgkey -private <你的私钥>   # 由已有私钥推导公钥
```

> 不需要额外安装 `wireguard-tools`（`wg genkey` / `wg pubkey`），本程序自带。

### 怎么填

直接照抄服务商给的 `wg-quick` 配置文件即可，字段一一对应：

| wg-quick 里的字段 | ChainProxy 对话框 |
|---|---|
| `[Interface] PrivateKey` | 私钥 |
| `[Interface] Address` | 隧道地址（如 `10.8.0.2/32`） |
| `[Peer] PublicKey` | 对端公钥 |
| `[Peer] PresharedKey` | **预共享密钥**（可选，但服务商开了就必须填） |
| `[Peer] Endpoint` | 服务器 + 端口（如 `192.168.31.94` + `51820`） |
| `[Peer] AllowedIPs` | AllowedIPs（如 `0.0.0.0/0, ::/0` 或 `192.168.31.0/24, 10.8.0.0/24`） |
| `[Peer] PersistentKeepalive` | Keepalive（常见 25） |
| MTU | MTU（默认 1420，连不上可试 1280） |

**密钥格式**：base64（wg 工具默认）与 hex 都支持，直接粘贴即可。

> **最容易踩的坑**：服务端的 peer 配置里，必须填**本端公钥**（由你的私钥推导出来的那个）。
> 公钥对不上时 WireGuard 只会**静默丢包**，不报任何错。
> 本程序在日志里会把「本端公钥」打出来，复制它去比对服务端配置即可。

### 前置代理怎么选

| 服务端位置 | 前置代理 |
|---|---|
| 公网地址（境外 VPS / 住宅 WG 出口） | 需要前置 —— 这正是本程序的核心用法 |
| **局域网地址**（如 `192.168.31.x`） | 用「直连」；用主流客户端也能通（主流客户端默认放行私有地址），但没必要 |

### 怎么判断通没通

看日志：

```
隧道已建立，出口经 192.168.31.94:51820
设备状态：
  last_handshake_time_sec=1759xxxxxx     ← 非 0 就是握手成功了
  tx_bytes=...   rx_bytes=...            ← 两个都在涨说明双向都在跑
```

失败时会给明确提示，而不是静默卡住：

```
WireGuard 握手超时（12 秒）：请确认前置代理支持 UDP、服务端地址/密钥正确，且服务端未被墙
```

同时会打印设备状态，便于区分"配置没生效"和"对端不回包"。

### 「能访问局域网」和「能当公网出口」是两件事

WireGuard 只把 **AllowedIPs 里列出的网段**送进隧道，别的流量根本没有路由。实测：

| 你的 AllowedIPs | 结果 |
|---|---|
| `192.168.31.0/24, 10.8.0.0/24` | 能访问家里的路由器/设备（实测连 `192.168.31.1:80` 成功）；**公网访问会被拒绝** |
| `0.0.0.0/0` | 所有流量进隧道；但**能不能出去取决于服务端有没有开 NAT/转发** |

判断方法很简单：把 AllowedIPs 设成 `0.0.0.0/0` 后测试。
- 能拿到公网 IP → 服务端已做 NAT，可以当出口用；
- 返回 `connection refused` → SYN 进了隧道、但服务端拒绝转发，**服务端还需要**：
  1. peer 的 AllowedIPs 设为 `0.0.0.0/0`；
  2. 打开 IP 转发（`net.ipv4.ip_forward=1`）；
  3. 配置 NAT（`iptables -t nat -A POSTROUTING -s 10.8.0.0/24 -j MASQUERADE`）。

换句话说：**「经隧道访问家里局域网」和「把家里宽带的公网 IP 当住宅出口」是两种配置**，
后者必须在服务端放行转发，客户端改 AllowedIPs 是不够的。

### 已知限制

- 本程序当前**不转发客户端侧的 UDP**（浏览器的 QUIC / DNS-over-UDP 不会被代理），
  TCP 流量不受影响。
- 隧道内的域名解析采用"**本地解析后送入隧道**"。若目标域名在本地被污染，
  需要在配置里走 TCP 或后续版本增加"隧道内解析"选项。

## 7. 数据在哪里

| 路径 | 内容 |
|---|---|
| `data\config.json` | 配置（含住宅代理账号密码，**请勿分享**） |

没有就用 exe 同级的 `data\`。
