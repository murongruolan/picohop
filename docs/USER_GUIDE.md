# PicoHop 使用手册

> 面向使用者的完整说明。想知道"为什么这么设计"请看
> [`ARCHITECTURE.md`](ARCHITECTURE.md)；想快速上手看
> [`../README.md`](../README.md)。

---

## 1. 它解决什么问题

你有一个前置代理（通常是主流客户端，监听 `127.0.0.1:10808`），
还有一个住宅 IP 服务商。日常上网不需要住宅 IP，但个别对 IP 敏感的网站必须用。

PicoHop 把这两者串成链，并给每个出口开一个**独立的本地端口**：

```
浏览器 → 127.0.0.1:10810 → (前置) → 住宅代理 → 目标网站
浏览器 → 127.0.0.1:10811 → (前置) → 另一个节点 → 目标网站
```

于是你可以按需在浏览器/软件里切换端口，而不是反复改全局代理设置。

## 2. 启动界面

双击 `dist\PicoHop.exe`。（`dist\picohop-cli.exe` 是**命令行版**，不是界面。）

界面从上到下三块：

1. **顶栏**：品牌与运行状态点、节点统计（运行中/总数）、今日流量、活动连接数、
   全局前置状态（点一下进设置），右侧是「导入」「添加节点」「全部激活」「全部停止」、
   主题切换、日志、设置。
2. **筛选栏**：别名搜索、状态筛选、列显示、测试。
3. **节点列表**：默认 8 列。

窗口默认 1180×740，最小 920×580；可以自由缩放，窄的时候顶栏里次要的统计会自动收起。

### 「添加 / 编辑节点」是一个独立窗口

点「添加节点」（或双击某一行编辑）时，对话框**不在主窗口里**，而是单独开一个
无边框、永远置顶的小窗口。这样做的意义：

- **可以拖到主窗口外面**，甚至拖到另一个显示器上，主窗口不会把它裁掉；
- **永远压在主窗口（以及别的程序）上面**，不会切一下窗口就找不到了；
- 拖它的**标题栏**就能移动它 —— 标题栏整条都是窗口的拖动把手，横向纵向都能拖。
- 关掉它有三个等价方式：右上角 ×、按 Esc、点「取消」。

> 为什么不用"主窗口里的弹窗"：Web 页面里的浮层只能画在所属窗口的客户区里，
> 一旦拖到窗口边缘就会被裁掉 —— 这是浏览器渲染方式的硬限制，不是设置问题。
### 扫码识别不会留下任何缓存文件

顺带说明一句：屏幕圈选与二维码识别**全程只在内存里**，识别完不留任何缓存产物。
`internal/qrscan` 包里没有任何写文件的调用；截下来的图是一块内存（`image.RGBA`），
用完即被回收，而且现在只截**选区那一小块**（不是整屏）。
`data\` 目录下永远只有 `config.json`、`picohop.log` 和 WebView2 的 `webview\`。
唯一会往磁盘写图片的是「分享 → 下载图片」，那是你自己选路径保存的结果。
### 托盘常驻（关窗不等于退出）

这是个"要一直开着"的工具，所以：

- **点右上角的 × 不会退出程序**，只是把窗口收进系统托盘。代理、本地端口、
  正在进行的连接都不受影响；第一次收进托盘时会弹一条 Windows 通知提醒你。
- **想真正退出**：右键托盘图标 →「退出 PicoHop」，或者界面右上角那个退出按钮。
- **左键单击托盘图标** = 把窗口叫回来。
- **托盘右键菜单**：显示主窗口 / 激活全部节点 / 停止全部节点 / 复制本地代理地址 / 退出。

> Windows 11 会把**新注册**的托盘图标默认放进 `^`（折叠区）。
> 没看到图标就去点一下那个 `^`，可以把它拖到任务栏上固定。

### 全局快捷键（窗口不在前台也生效）

| 快捷键 | 作用 |
|---|---|
| `Ctrl+Alt+C` | 显示 / 隐藏主窗口 |
| `Ctrl+Alt+Shift+A` | 激活全部节点；若已有节点在跑，则全部停止 |

这两个键**可以自己改**：设置 →「快捷键」。点一下输入框就开始录制，
然后按下你想用的组合键（至少要两个键：一个 Ctrl/Alt/Shift 加一个普通键；
只按一个键会被拒绝，旁边会提示"请点击键盘两个以上组合键进行记录"）。
点「清除」可以把某一条关掉（显示为「未启用」），它就不再占用任何组合键。

> 默认值为什么不是 `Ctrl+Alt+A`：那个组合被微信 / QQ 的截图占用了，
> 装了它们就抢不到，所以默认改成 `Ctrl+Alt+Shift+A`。

快捷键被别的程序占用时**不会打断启动**：保存后会弹一次提示、日志里也会写明
是哪一条被谁占用了（`data\picohop.log` 里搜"全局快捷键"）。

## 3. 添加第一个节点

点「添加节点」。对话框里字段的顺序是刻意安排的 ——
**「本地代理端口」排在所有协议参数之前**，因为它是最常要看要改的一项。

### 3.1 基本信息

| 字段 | 说明 |
|---|---|
| 别名 | 列表里显示的名字，必填 |
| 类型 | 八选一，见下表 |
| **本地代理端口** | 默认已算好（从 10810 起排，取全部 10800+ 端口最大值 + 1）。旁边有「随机」按钮；手工输入后**失焦即检测占用**，被占用会红字提示并说明是被哪个节点占的 |
| 前置节点 | 直连 / 全局前置代理 / 项目内某个节点，见第 4 节 |
| 服务器地址·远程端口 | 出口服务器的地址与端口 |
| 备注 | 可选 |

### 3.2 各协议要填什么

| 类型 | 需要填的字段 |
|---|---|
| **SOCKS5** | 服务器、远程端口、（可选）用户名密码 |
| **HTTP** | 同上 |
| **WireGuard** | 服务器=Endpoint 地址、远程端口=Endpoint 端口、本端私钥、对端公钥、隧道地址（如 `10.7.0.2/32`）；可选预共享密钥、AllowedIPs、Keepalive、MTU。对话框里有「生成密钥对」按钮，会把**公钥**自动复制到剪贴板，你把它交给服务端登记即可 |
| **VMess** | UUID、AlterId、加密方式（通常 `auto`）、传输层（tcp/ws/grpc/http/httpupgrade）、TLS |
| **VLESS** | UUID、流控 Flow（一般留空，只有 Vision 才填 `xtls-rprx-vision`）、传输层、TLS（**Reality 也在这里填**：公钥 pbk / ShortId / SpiderX） |
| **Shadowsocks** | 加密方法、密码 |
| **Trojan** | 密码、传输层、TLS（**强制**） |
| **Hysteria2** | 密码、上下行 Mbps（0 表示不声明）、混淆类型与密码、PinSHA256、TLS（**强制**） |

几个容易踩的点：

- **Reality 必须启用 TLS**，而且「指纹」建议选 `chrome`（Reality 依赖 uTLS）。
- **流控 Flow 大多数情况要留空**。填了 `xtls-rprx-vision` 就必须是 TCP + TLS。
- **WireGuard 的 Keepalive 建议 25**。填 0 且没有数据要发时，
  WireGuard 不会主动发起握手，表现为"一直在连、就是连不上"。
- 传输层选 `tcp` 时不需要填路径/Host；选 `grpc` 时填服务名，其它传输填空格里的路径与 Host。

### 3.3 从分享链接 / 二维码导入

- 「添加节点」对话框顶部有「从剪贴板导入分享链接」与「从屏幕扫描二维码」；
  顶栏的「导入」菜单里也有，另外还有一个「手动粘贴链接…」。
- 识别成功后**不会直接入库**，而是弹一个**只问本地端口**的小窗口：
  每个节点一行，默认端口已填好，可以逐个改或点「随机」。
- 支持一次导入多条。

**屏幕扫描二维码怎么用**：点「从屏幕扫描二维码」→ 主界面会暂时隐藏 →
屏幕上出现整屏遮罩、鼠标变成红色十字准星 → 按住左键拖拽圈出二维码 →
松开后立即识别并弹出端口窗口。圈选时按 `Esc`、点右键、或者选区太小都会被当成取消。

## 4. 「前置节点」怎么选

三种选法，决定了这条链路的第一跳：

| 选择 | 含义 | 典型场景 |
|---|---|---|
| **直连（不使用前置）** | 直接连出口服务器 | 出口服务器本身就能直连（例如局域网里的 WireGuard 服务端、国内可直连的节点） |
| **全局前置代理** | 走设置里那一个 | 出口是住宅代理，必须经非大陆 IP 才能连上 |
| **节点「XXX」** | 用那个节点的本地端口当前置 | 想串两条链路，例如 `中转节点 → 落地节点` |

选第三种时：

- 激活外层节点会**自动先把前置节点启动起来**（按依赖顺序），
  界面会提示"将连带激活前置节点"；
- 界面会**自动屏蔽会形成环路的选项**，后端也会再校验一次；
- 停止内层节点时，依赖它的外层节点会被**一起停止**（否则会指向一个没人监听的端口）。

## 5. 激活与日常使用

- **单击**一行选中；**Ctrl + 单击**加选；**Shift + 单击**范围选。
- **按回车激活**选中的节点（这是主要操作方式）。
- **双击**进入编辑。
- **右键**弹出菜单，操作对象是"当前选中集合"。
- 激活成功后，该节点就在 `127.0.0.1:<本地端口>` 上监听，
  同时接受 **SOCKS5** 与 **HTTP** 客户端。

右键菜单项：

| 菜单项 | 说明 |
|---|---|
| 激活节点 / 停止节点 | 等价于回车 |
| 编辑 / 克隆此项 | 克隆会分配新 ID 与新端口，并且不继承统计 |
| 复制本地代理地址 | 复制 `127.0.0.1:端口` |
| 测试所选 TCP 延迟 | 不经代理，只对服务器地址做一次 TCP 握手；最快 |
| 测试所选真连接延迟 | 走完整链路取样多次（默认 2 次）取最小值；最准 |
| 测试所选速度 | 走完整链路下载若干秒后算 MB/s（超时会主动断开） |
| 检测所选出口 IP | **判断链路是否真的生效**：和前置出口 IP 不同才算成功 |
| 分享 | 二维码 + 链接文本 + 下载图片 / 复制文本 |
| 清零今日统计 | |
| 移除所选 | 正在运行的会先被停止并释放端口 |
| 移除测试无效项 | 删掉"连服务器地址都握不上手"（TCP 延迟为 0）的节点 |

快捷键：`回车` 激活、`Delete` 移除、`Ctrl+A` 全选可见项、`Esc` 关菜单。
筛选栏里也有一个「测试」下拉，作用相同但作用于"选中的（没选就全部）节点"。

### 「真连接延迟」量的到底是什么

它走完整链路请求测试地址（默认 `https://www.google.com/generate_204`），
**取样多次、结果取最小值**（次数在「设置 → 测试」里改，默认 2 次）。两个数要分清：

- **冷连接**（第 1 个样本）：含 TCP 建链、前置与节点的协议握手、TLS —— 这是
  "第一次打开网页"的真实代价。把取样次数设成 1，你看到的就是它。
- **最小值**（第 2 次起）：连接会被复用，量到的是"隧道已经建好之后一次 HTTP 往返"。
 主流客户端的「测试真连接延迟」就是这个口径（它同样循环两次、取最小值），
  所以**两个软件的数字可以直接对照**。

一次测试在日志里会有两行：先一行是全部样本
（`真连接延迟取样 1090/210 ms（冷连接 1090 ms，取最小 210 ms）`），再一行是结果。
冷连接与最小值差得远，说明慢在建链（协议握手 / TLS）而不是链路本身。

## 6. 列表的列

默认显示：**类型、别名、本地端口、地址、远程端口、传输协议、延迟(ms)、速度(MB/s)**。

点「列显示」可以额外打开：

| 列 | 说明 |
|---|---|
| 状态 | 已激活 / 未激活 / 错误 |
| 真连接(ms) | 真连接延迟 |
| 出口 IP | 最近一次「检测出口 IP」的结果 |
| 今日统计 | 今日双向流量，自动换算 KB/MB/GB/TB/PB（悬停看上传/下载明细） |
| 最近使用 | 相对时间，悬停看精确时间 |
| 创建时间 | |
| 备注 / 前置 / TLS / 活动连接 / 累计连接 | |

勾选结果会记住。别名列前面那个**小圆点**就是状态：绿=已激活、红=错误、灰=未激活。

「本地端口」那一格**点一下就复制** `127.0.0.1:端口`。
正在测试的节点会在对应格子里显示转圈，所以一眼能看出在测哪一项。

## 7. 设置

设置面板有四个标签页，刻意只放"真的会用到"的项：

**前置与网络**
- 全局前置代理：类型（socks5 / http / 直连）、地址、端口、账号密码，
  以及一个「测试前置代理连通性」按钮（会显示前置的出口 IP 与延迟）。
- 允许局域网连接（底部栏 → 网络设置）：打开后节点监听 `0.0.0.0`（局域网其它设备可用）。
  **打开后每个节点都必须配齐本地端口鉴权（编辑节点 → 高级 → 本地端口鉴权：
  用户名和密码都要填）**，否则该节点会被**拒绝启动** —— 监听局域网又没有凭据，
  等于给整条网段开了一个匿名开放代理，任何人都能借这台机器出去。
  默认关闭，只监听回环；只监听回环时无需鉴权。
- 起始端口：新增节点时的默认端口从这里开始排（默认 10810）。

**测试**
- TCP 超时、并发数、真连接地址、取样次数、测速地址、测速时长。

**运行与界面**
- 空闲自动断开秒数。
- 启动时自动激活上次处于激活状态的节点。
  **注意：这与"开机自启动"无关 —— 本程序任何情况下都不注册自启动。**
- 主题（跟随系统 / 深色 / 浅色）、通知停留时长、日志保留行数。

**关于**
- 版本、内嵌引擎状态、配置文件与数据目录位置，以及三个「打开目录」按钮。

## 8. 命令行（排障用）

界面出问题、或者想写脚本自动化时用 `dist\picohop-cli.exe`：

```powershell
picohop ls                    # 看节点与状态
picohop fetch                 # 看前置与各节点的出口 IP（最常用）
picohop test -kind real       # 跑测试：tcp / real / speed / exit
picohop run -seconds 30       # 前台跑一会儿（脚本里用）
picohop validate              # 只校验配置
picohop import "<分享链接>"    # 导入
picohop express <节点>        # 导出分享链接
picohop engines               # 检查内嵌引擎构建标签
picohop wgkey --psk           # 生成 WireGuard 密钥对
```

常用参数：`-config <路径>`（默认自动定位到项目里的 `data\config.json`）、
`-node <ID或别名>`。

## 9. 故障排查

### 节点激活失败

界面会红字给出原因，常见几种：

| 提示 | 原因与处理 |
|---|---|
| 端口 xxx 已被「YYY」占用 | 本项目内另一个节点在用这个端口。改端口，或点「随机」 |
| 端口 xxx 已被本机其它程序占用 | 用 `netstat -ano | findstr :端口` 找出占用者，或换个端口 |
| 端口 xxx 绑定失败 | 同上，也可能是被系统保留（`netsh interface ipv4 show excludedportrange protocol=tcp`） |
| 出口启动失败: 端口 x 绑定失败 | 出口已起的部分被回滚，具体错误看日志 |
| WireGuard 握手超时 | 见下面单独一节 |

### 「检测出口 IP」显示与前置相同

说明流量没有真正走这个出口。按顺序检查：

1. 这个节点的「前置节点」是不是选错了（例如本该直连却挂了全局前置）；
2. 出口服务器的账号密码/端口是否真的能用；
3. 用 `picohop fetch` 对照着看前置与各节点的出口 IP。

### WireGuard 连不上

WireGuard 协议本身**不会告诉你**是密钥不对还是网络不通，所以按顺序排除：

1. **前置必须支持 UDP**。WireGuard 的外层是 UDP；如果你用的是 HTTP 前置，
   它天然不支持 UDP。`picohop fetch` 只能测 TCP，
   UDP 能力要用 `scripts\test_wg.ps1` 测（它第 [0] 步就是查前置的 UDP 能力）。
2. **公钥/私钥配对**：私钥是本机的、公钥是服务端的，两者不能搞反。
   用 `picohop wgkey -private <你的私钥>` 可以反推公钥来核对。
3. **PresharedKey**：服务端如果开了，客户端不填会一直握手失败。
4. **AllowedIPs**：一般 `0.0.0.0/0, ::/0`；只想走隧道到内网就填内网网段。
5. **Keepalive**：填 25。填 0 且没有数据要发时不会主动发起握手。
6. 看日志里的「设备状态」：能看到 `public_key / endpoint / allowed_ip` 就说明
   配置进去了；再看 `tx_bytes / rx_bytes` 判断包有没有发出去、有没有收到回包。

### Reality / Hysteria2 节点激活时报「mihomo 适配层暂不支持…」

说明节点的某个字段 mihomo 接不了（例如 REALITY 没填「指纹」、vmess 用了 xhttp 传输、
trojan 用了它没有的传输选项）。**这不是构建问题**：内核是内嵌的 mihomo、不需要任何构建标签
（`with_utls` / `with_quic` 那套已随 sing-box 一起删除）。
按日志里那句错误改节点配置即可；用 `picohop engines` 可以确认内核确实被编进来了。
（历史上这条曾经是"缺少构建标签"，那条路已不存在。）

### 导入的链接解析不了

- 支持 `vless://`、`vmess://`、`ss://`、`trojan://`、`hysteria2://`（含 `hy2://`）。
- `socks5://`、`http://`、`wireguard://` **没有通用的分享格式**，请手工添加。
- 未知参数会被忽略，不影响解析；如果整条解析失败，日志里会打出识别到的原文。

### 界面显示不出来 / 花屏

试着在设置里把主题从「跟随系统」切成明确的「深色」或「浅色」。

## 10. 数据与安全

- 配置在 `data\config.json`，**明文**保存账号密码与密钥，请注意本机安全。
- 它已被 `.gitignore` 排除。**不要**把它提交到仓库或发给别人。
- 分享链接里包含节点的全部连接凭据，只分享给自己信任的人。
- 本程序不写注册表、不建计划任务、不装服务、不注册开机自启动。
- 默认只监听 `127.0.0.1`，不会触发 Windows 防火墙提示。
