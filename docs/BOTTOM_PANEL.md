# 底部栏目（Bottom Panel）设计约定

> 这份文档是**实现契约**：动手前先读它，改动与它冲突时先改文档再改代码。
> 界面文案规则见文末 —— 上一轮 UI 的问题是说明文字过多，这里明确禁止。

## 1. 为什么做

- 列表的**横向滚动条贴着窗口底边**，不好按住；
- 窗口底部大片空白，看着"空"；
- 日志只能开对话框看，且无法一边看列表一边看日志（主流客户端的做法值得借）。

## 2. 结构

```
工具栏
过滤栏
┌──────────────────────────────────────────────────────────┐
│ 节点表格                       ← 横向滚动条抬到下面这条栏之上 │
├──────────────────────────────────────────────────────────┤ ← 4px 拖拽调高
│ ⌄ │ 流量统计 网络设置 日志 网站测试 连接 │  状态区          │ 34px 常驻
├──────────────────────────────────────────────────────────┤
│ 身体：随头部切换的内容（可收起、高度可拖、高度持久化）        │
└──────────────────────────────────────────────────────────┘
```

- **头部常驻 34px**：滚动条永远离底边 34px；状态信息常在，底部不空。
- **点当前视图按钮 = 收起**（与 `⌄` 等价）。
- **高度持久化**：`Settings.bottomPanel{View, Height, Collapsed}`。
- 收起时只留头部；身体不渲染（省掉表格重绘）。

### 头部右侧状态区

| 元素 | 内容 | 点击 |
|---|---|---|
| 本地 | `10810 / 10811` | 复制地址 |
| 前置 | `● 10808`（绿/红） | 测前置连通性 |
| 速率 | `↑ 12.4K ↓ 3.1M` | 打开流量统计 |
| 错误 | `● 3`（有错误才显示） | 跳到第一条错误 |

## 3. 五个视图

| 视图 | 布局 | 内容 |
|---|---|---|
| 流量统计 | 左 2/3 折线图，右 1/3 指标格 | 图：上传/下载双线 + `1分钟 / 10分钟 / 1小时`；格：上传速度、下载速度、活跃连接、上传量、下载量、内核占用 |
| 网络设置 | 单列 | **迁入已有项**：起始端口、允许局域网、系统代理、TUN。不做空壳页签 |
| 日志 | 左：`用户日志`/`网络日志` 竖排按钮；右：过滤器 + 清除本项 + 自动滚动到末尾 | 过滤器占位符 `过滤器（支持正则）`，内嵌搜索图标，**回车触发** |
| 网站测试 | 左 2/3 网站卡片，右 1/3「我的 IP 信息」 | 卡片：Apple/GitHub/Google/YouTube 默认 + 自定义；单个测试 + 全部测试。IP 区见下 |
| 连接 | 顶部 `活跃 / 已关闭` + 过滤 + 关闭全部 | 表格：主机、规则、链路、上传、下载、时长、源端口 |

### 「我的 IP 信息」

- **查的是本机自己的 IP（直连）**，不是出口 IP。→ 请求必须**显式绕过系统代理**发出，
  否则会被系统代理带走、拿到出口 IP，与需求相反。
- 展示：国家（旗+名称）、服务商、组织、IP（**默认脱敏**，旁边小眼睛点击显示）、
  位置、时区、自治域、大致经纬度、自动刷新倒计时（可手动刷新）。

## 4. 三个附加功能（省事向，不是装饰）

1. **按节点流量排行**（流量统计内）：多节点时一眼看出流量走了哪个。
2. **网站 × 节点可达性矩阵**（网站测试内）：不只"通不通"，而是"**经哪个节点通**"。可切换为"只测当前链路"。
3. **日志错误徽标**（头部状态区）：点击直达第一条错误。

## 5. 后端改造（不是 UI 能变出来的）

| 能力 | 做法 |
|---|---|
| 网络日志 | 在内嵌 sing-box 的 `log` 上挂 writer → 环形缓冲 → 事件推给界面 |
| 连接 + 逐连接流量 | 启用 sing-box `experimental.主流客户端_api`（或引擎层自统计）后轮询 |
| 用户日志 | 已有 `data/chainproxy.log`，加环形缓冲 + 事件 |
| 网站测试 | 逐个站点发 HEAD/GET，记录耗时与状态 |
| 本机 IP 信息 | 直连（绕过系统代理）查一次，带倒计时自动刷新 |

## 6. 界面文案规则（硬性）

- 界面只放**标签 + 值**；解释一律进 tooltip 或删除。
- 一句话不超过一行；能用状态色/图标表达的不用文字。
- 新面板**零说明句**。
- 待清理（纯减法，不改行为）：`SettingsDialog` 10 处 `cp-hint`、`NodeDialog` 4 处。

## 7. 施工顺序

1. 骨架：头部 + 收起/展开 + 拖高 + 状态区 + 持久化（先把滚动条抬高这件事落地）
2. 流量统计（含按节点排行）
3. 日志（用户日志 → 再接 sing-box 日志流做网络日志）
4. 网站测试 + IP 信息（+ 可达性矩阵）
5. 连接（内核自带的 RESTful API）
6. 网络设置（迁入已有项）
7. 文案瘦身
